# Contribution Guide

Thank you for improving `vibe-coding-architecture-skill`.

Good contributions make the Skill clearer, more beginner-friendly, and more useful before implementation begins.

## Ways to contribute

- Add new examples in `examples/`
- Add new common patterns in `references/common-patterns.md`
- Add new tech stack guide entries in `references/tech-stack-guide.md`
- Improve beginner explanations in `references/beginner-glossary.md`
- Submit new evaluation cases in `evals/sample-eval-cases.md`
- Improve multilingual README consistency

## Writing style

- Explain conclusions first.
- Use simple language without sounding childish.
- Avoid jargon dumping.
- Explain why each technical choice fits the current stage.
- Separate MVP needs from future expansion.
- Tell users what not to build yet.

## Pull request checklist

Before opening a PR, check:

- The change supports architecture planning before coding.
- The content is useful for beginners.
- No unnecessary scripts or package files are added.
- README translations remain semantically consistent when core behavior changes.
- Examples include MVP scope, data model, API Contract, risks, and Build Brief.
- The Skill still avoids over-engineering.
