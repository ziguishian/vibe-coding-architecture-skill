# Architecture Consultation Question Bank

Use these questions when the product idea is incomplete. Ask only the most relevant 5-10 questions at a time.

## 1. Product goal

- What problem should this product solve?
- Who feels this problem most often?
- What should the user be able to finish in one successful session?
- Is this for personal use, team use, or public customers?
- What does success look like for the first version?
- What must be true before you feel the MVP is useful?

## 2. User roles

- Who will use the product?
- Is there an admin role?
- Are there normal users and paid users?
- Can users see each other's data?
- Does anyone need approval or review permissions?
- Will team members collaborate in the same workspace?

## 3. Core features

- What is the one feature users come for?
- What input does the user provide?
- What output should the product generate or display?
- What can be delayed until later?
- Which feature would make the first version too complex?
- Does the product need search, filters, export, or sharing?

## 4. Pages and interaction

- What screens does the user need to complete the main task?
- What should the homepage or first screen show?
- Does the user need a dashboard?
- What actions happen on each page?
- What error messages should users see?
- Does the product need mobile-friendly screens?

## 5. Data types

- What information must be saved long term?
- Is the data mostly text, records, files, or temporary state?
- Does the product need history records?
- Should users be able to delete or export their data?
- Is any data sensitive?
- What data can be regenerated instead of stored?

## 6. Permission system

- Does the product need login?
- What can guests do?
- What can logged-in users do?
- What can admins do?
- Are there paid features or quotas?
- Should users only access their own data?

## 7. AI capabilities

- What should AI generate, classify, summarize, or analyze?
- What user input goes into the AI model?
- Should AI output be saved?
- What should happen if the AI API fails?
- Is streaming output needed?
- Is there a monthly budget for model usage?

## 8. Files and media

- Will users upload images, PDFs, spreadsheets, or videos?
- Will the system generate downloadable files?
- Are files private or public?
- How long should files be kept?
- Is preview, resizing, or conversion needed?
- What is the expected file size?

## 9. Payment and monetization

- Is the first version free, paid, or invitation-only?
- Do users need subscriptions?
- Are there usage quotas?
- Which payment provider is preferred?
- What happens when a user's quota runs out?
- Can payment be delayed until after MVP validation?

## 10. Automation and task queues

- Does any task take more than a few seconds?
- Should users see task progress?
- Are retries needed when tasks fail?
- Does anything run on a schedule?
- Does the product need batch import or export?
- Can the first version process tasks manually instead?

## 11. Deployment environment

- Should the product run locally, on the web, or both?
- Which regions will users access it from?
- Is a managed platform acceptable?
- Is there an existing domain?
- Who will maintain the deployment?
- Are there company or compliance restrictions?

## 12. Budget and maintenance ability

- What monthly budget is acceptable for the MVP?
- Are paid APIs involved?
- Can the owner maintain servers?
- Is simplicity more important than full control?
- What happens if traffic grows suddenly?
- Is vendor lock-in acceptable at the MVP stage?

## 13. Security and privacy

- Does the product store personal data?
- Does it store customer business data?
- Does it store prompts, documents, or generated content?
- Who can view logs?
- Is data deletion required?
- Are API keys protected on the backend?

## 14. Future expansion

- What features might be added after validation?
- Could this become a team product?
- Will mobile apps be needed later?
- Will more AI models or providers be added?
- Will the product need analytics or reporting?
- What must stay flexible now to avoid painful rewrites later?
